# Чергування лікаря: CRUD-сервіс і вимірювання масштабованості

Навчальний проєкт з дисципліни "Високопродуктивні розподілені обчислювальні системи".
Кожна з двох лабораторних робіт знаходиться в окремому репозиторії, але ЛР2 доповнює сервіс ЛР1, а не замінює його.

Стек: Python 3.12, FastAPI, psycopg 3 (пул зʼєднань), PostgreSQL 16, nginx 1.27, Prometheus,
Docker Compose. Генератор навантаження і всі скрипти вимірювань — лише стандартна бібліотека
Python (matplotlib потрібен тільки для діаграм).

## Дві лабораторні і два варіанти
| | Лабораторна 1 | Лабораторна 2 |
| --- | --- | --- |
| Про що | Проєктування і розгортання CRUD-сервісу | вимірювання межі масштабованості |
| Варіант | **22** | **21** |
| Звіт | [REPORT.md](REPORT.md) | [REPORT-LAB2.md](REPORT-LAB2.md)|
| Запуск | [RUN.md](RUN.md) | [RUN-LAB2.md](RUN-LAB2.md)|
| Посилання на репозиторій | https://github.com/DianaSamoray/service-fastapi | https://github.com/DianaSamoray/service-fastapi-lab2 |

**Про номер варіанта.** ЛР1 виконана за варіантом 22: сутність "чергування лікаря", ресурс `/shifts`,
фільтр за відділенням, валідація тривалості чергування 4-24, ліміти контейнера 1 CPU і 768 МБ.
ЛР2 виконана за варіантом **21**: розмір пулу з'єднань 5, набір бакетів гістограми Г3
(1, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024 мс), додаткова метрика М4 (частка запитів з тривалістю обробки,
не більшою за поріг, обчислена за лічильником бакета гістограми). Ліміти CPU і пам'яті взяті з ЛР1 і
не змінювались, як того вимагає умова. Сам сервіс під варіант 21 не переписувався.
